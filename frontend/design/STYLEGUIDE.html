Style Guide — Wind Forecast Decision Portal

Locked direction: F — Publication Moment · Subject-derived visual language · Frozen system

1. Premise & Source Boundary

Subject: Wind Forecast Decision Portal for UK utility traders. Traders make high-stakes decisions at D-1 09:00 London cutoff using forecast vintages. Tension: certainty vs uncertainty, forecast vs actual, now vs later, buy vs shortfall risk.

Derived mechanism: The "as of" timestamp is the dominant mark. Everything not essential to the decision moment recedes. No look-ahead bias—only what was known at cutoff.

Source boundary: Round 1 typography-led directions A–J. Direction F selected by explicit human lock. No Round 2 code proceeds without a locked direction.

4. Hierarchy & Composition Rules

  • Moment first: The "as of" timestamp is set in large serif display (#111827) at the top of each decision context.
  • Data in mono: All numerals (MW, MWh, timestamps) set in monospace with tabular-nums for vertical alignment.
  • No color as decoration: Color is used only for moment (ink) and context (muted). No blue, green, red, amber accents for status—use weight, size, and position instead.
  • No borders as ornament: Borders only where functionally necessary (card separation, input fields).
  • Whitespace as structure: Generous whitespace separates sections; the half-hour grid (48 periods) informs the spatial rhythm.

6. Language Behavior

  • Cutoff hour expressed 0–23, London timezone (Europe/London).
  • Dates as YYYY-MM-DD; timestamps ISO 8601, rendered in London time.
  • Positive error = over-forecast = shortfall risk for buyer (error_mw = forecast_mw - actual_mw).
  • "As of" phrasing dominant: what was known at cutoff, nothing after.

7. Responsive Variation

Desktop-first (traders use multi-monitor). Sidebar collapses below 1024px (lg breakpoint). Font sizes scale down on mobile; moment display remains serif but smaller. Charts stack vertically below lg breakpoint.

8. Accessibility Boundaries

  • Color never sole carrier of meaning (2-color palette; status via weight/position).
  • Focus rings on interactive elements (2px ring, offset-2).
  • Minimum touch target 44px for buttons/inputs.
  • Dark mode contrast meets WCAG AA (moment #ffffff on bg #0f172a = ~15.6:1).

9. Invariants & Prohibited Normalization

  • ECharts theme registered once at module load (echartsTheme.ts)—never per-component.
  • No new dependencies (no font packages, chart libs, UI kits).
  • No backend/API client changes—frontend only.
  • No Google Fonts, no external font CDN.
  • Dark mode charts use explicit color overrides (ECharts does not inherit CSS).
  • No borders, shapes, icons, images, gradients, shadows, SVG in Round 1 directions.

10. Asset / License Status

  • Fonts: System stacks—no license, no self-hosted assets.
  • Charts: echarts ^5.4.3 + echarts-for-react ^3.0.2 (existing, Apache-2.0 / MIT).
  • Icons: Inline SVG only (theme toggle, status marks)—no icon library.

11. Copyable Continuation Prompts
