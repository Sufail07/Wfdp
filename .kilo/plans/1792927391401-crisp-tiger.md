# Plan: Mitigate All Current Issues in Wind Forecast Decision Portal

## Overview
This plan addresses all issues identified in REPO_ANALYSIS.md, organized into P0 (critical), P1 (high-priority), and P2 (polish) categories. The system will transition from synthetic data presentation to either real data ingestion or transparent synthetic labeling, while fixing performance, feature gaps, and technical debt.

## P0: Must Be Done (4-5 hours)

### P0.1: Data Integrity Fix
**Problem**: Synthetic data presented as real Elexon data (C1)  
**Solution**: Replace mock data with real Elexon data or disclose as synthetic everywhere

**Files to modify**:
- `backend/ingest/generate_mock.py` - remove or replace with real ingestion
- `manifest.json` - update dataset_version to reflect synthetic status
- `README.md` - clarify data source and labeling
- `frontend/src/features/method/Method.tsx` - add synthetic disclosure
- All chart footers and UI elements displaying "Source: Elexon BMRS" - add synthetic label

**Implementation**:
1. First attempt: Probe current Elexon Insights API (`data.elexon.co.uk`) and save real fixtures
2. Include required date range: forecasts from 30-31 Dec, actuals through 1 Feb
3. If real data impossible: Add "Data Disclaimer: This dataset contains synthetic mock data for demonstration purposes only. Real Elexon data not available." to all pages

### P0.2: Performance Optimization
**Problem**: Accuracy endpoints very slow (C4) - causes due to per-request loading and double bootstrap

**Files to modify**:
- `backend/app/main.py` - enhance cache with precomputation
- `backend/app/api/accuracy.py` - move snapshot loading to lifespan
- `backend/app/api/decision_forecast.py` - reuse cached snapshot
- `backend/app/domain/metrics.py` - compute bootstraps only for summary

**Implementation**:
1. Precompute all accuracy results at startup or build time
2. Load snapshot once in lifespan, pass cached data to handlers
3. Remove bootstrap loops from per-group computations
4. Cache computed metrics in memory keyed by parameters

### P0.3: Decision Brief Features
**Problem**: Decision Brief missing core features (C3) - no date picker, actuals overlay, vintages overlay

**Files to modify**:
- `frontend/src/features/brief/DecisionBrief.tsx` - add delivery date picker
- `frontend/src/features/brief/DecisionBrief.tsx` - use `useForecastRevisions` properly
- `frontend/src/api/endpoints.ts` - add actuals endpoint
- `frontend/src/features/brief/DecisionBrief.tsx` - fix fake cutoff line
- `frontend/src/features/brief/DecisionBrief.tsx` - derive coverage_start/end from data

**Implementation**:
1. Add delivery date picker with setter for DEFAULT_DATE
2. Implement actuals overlay for forecast vs actual comparison
3. Fix revisions endpoint to return N vintages (not rows)
4. Remove fake CSS cutoff line, implement proper cutoff line based on deliveryDate
5. Show real cutoff line positioned on D-1 based on current delivery date

### P0.4: Risk Band Fix
**Problem**: Risk band statistically wrong and leaks future (C5)

**Files to modify**:
- `backend/app/domain/risk.py` - fix margin calculation, look-ahead, bins
- `backend/app/api/risk_band.py` - add validation, proper error handling
- `frontend/src/features/risk/RiskBand.tsx` - show clear state for small samples

**Implementation**:
1. Change margin to unconditional quantile of signed error (P90)
2. Restrict history to days ≤ D-2 (exclude D-1 actuals)
3. Derive bins from data distribution instead of hard-coded values
4. Populate `over_forecast_quantile` field properly
5. Show "Not enough history" message instead of 404 for small samples
