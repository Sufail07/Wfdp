# Frontend Revamp Plan: Wind Forecast Decision Portal

## Current State Analysis

**Stack**: React 18 + TypeScript + Vite + Tailwind CSS + ECharts (echarts-for-react)
**Pages**: Decision Brief (dashboard), Forecast Accuracy, Method & Data
**Design System**: Generic Tailwind - Inter font, blue primary (#0ea5e9), gray neutrals, standard card layouts, dark mode

**Identified Issues**:
1. **Generic SaaS aesthetic** - Inter + blue + gray cards = indistinguishable from 1000s of dashboards
2. **No typographic hierarchy** - Single font, flat weight scale, no personality
3. **Standard spacing rhythm** - Tailwind defaults (4/6/8) with no subject-derived logic
4. **No visual language** - Color only on primary actions, not as hierarchy/composition tool
5. **Charts feel disconnected** - ECharts defaults, no integration with UI language
6. **Dark mode is superficial** - Just color inversion, no considered dark palette
7. **Navigation is forgettable** - Standard top bar, no spatial distinction

---

## Design Premise (Subject-Derived)

**Subject**: Wind Forecast Decision Portal for UK utility traders
**Context**: Traders make high-stakes decisions at D-1 09:00 London cutoff using forecast vintages
**Tension**: Certainty vs uncertainty, forecast vs actual, now vs later, buy vs shortfall risk
**Materials**: Time-series data, vintages (forecast revisions), MW/MWh, London timezone, half-hourly periods

**Derived Visual Mechanisms**:
- **Temporal rhythm** → Half-hourly grid (48 periods/day) becomes spatial rhythm
- **Vintage layers** → Forecast revisions as typographic layers/weights
- **Risk direction** → Over-forecast (shortfall risk) = warm, under-forecast = cool
- **Cutoff moment** → Hard temporal boundary = hard visual boundary
- **London timezone** → Meridian/greenwich reference = vertical alignment anchor

## Round 1: Typography-Led Directions (A-J)

Per the Innovative UX Designer V3 framework, create 10 independent HTML directions using only:
- Type, flat background color, text color, whitespace
- No borders, shapes, icons, images, gradients, shadows, SVG

Each direction gets its own premise from the evidence above.

| Direction | Premise | Font Strategy | Color Depth |
|-----------|---------|---------------|-------------|
| A | **Cutoff Line** - Hard temporal boundary as vertical rule | Monospace (data) + Sans (UI) | 2-color (boundary + content) |
| B | **Vintage Stack** - Forecast revisions as typographic depth | Variable font weight axis | 3-color (vintage layers) |
| C | **Half-Hour Grid** - 48-period rhythm as baseline grid | Tabular numerals, tight leading | 1-color (pure rhythm) |
| D | **Meridian Anchor** - Greenwich vertical as reading spine | Serif display + mono data | 2-color (anchor + data) |
| E | **Risk Polarity** - Over/under forecast as warm/cool text | Single variable font, weight/width axes | 4-color (polarity + neutral) |
| F | **Publication Moment** - "As of" timestamp as dominant mark | Display serif + mono | 2-color (moment + context) |
| G | **Buyer's Shortfall** - Shortfall risk as visual weight | Condensed sans, tight tracking | 3-color (risk + safety + context) |
| H | **Forecast Horizon** - Distance from cutoff as fade/scale | Single font, size/opacity gradient | 2-color (near + far) |
| I | **Actual vs Forecast** - Two voices, one timeline | Paired serif/sans dialogue | 3-color (forecast, actual, delta) |
| J | **Decision Window** - Narrow actionable moment | Wide sans, generous whitespace | 1-color (focused clarity) |

**Deliverables**: `A.html` through `J.html` + `index.html` (neutral comparison viewport)

- Dark mode as considered palette, not inversion

### 3. Page-Level Rebuilds
- **DecisionBrief**: New sidebar/main composition, KPI strip, main chart, AsOfCallout
- **Accuracy**: Metric cards, chart grid, distribution panel
- **Method**: Tab system, assumption/caveat cards, data lineage table

### 4. HTML Style Guide (`STYLEGUIDE.html`)
Self-contained, rendered in locked visual language, includes:
- Premise & source boundary
- Typography & font licensing
- Color roles & proportions
- Hierarchy & composition rules
- Spacing & rhythm
- Language behavior
- Responsive variation
- Accessibility boundaries
- Invariants & prohibited normalization
- Asset/license status
- Copyable continuation prompts

## Technical Approach

**No new dependencies** - Use existing stack (Tailwind, ECharts, React Router)
**CSS-first** - Custom properties for tokens, utility classes for composition
**ECharts theme** - Register custom theme from locked palette
**Dark mode** - Separate considered palette via `[data-theme="dark"]`
**Font loading** - Self-host or system fonts only (no Google Fonts per isolation)
