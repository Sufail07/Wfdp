```markdown
# Wind Forecast Decision Portal — Architecture Overview

## 1. Executive Summary
- One-paragraph system description
- Key constraints (Jan 2026 data, 09:00 London cutoff, Vercel/Docker)
- One-line per screen: Decision Brief, Accuracy, Method

## 2. System Context Diagram
- Mermaid or ASCII diagram showing: Elexon → Ingest CLI → Parquet Snapshot → FastAPI → React SPA

## 3. Data Flow & Lifecycle
- Ingestion (offline CLI → Pandera validation → Parquet + manifest)
- Serving (cold-start load → in-memory pandas → FastAPI → JSON)
- Frontend (TanStack Query → ECharts → React Router)

## 4. Core Domain Logic (The "Money Slide")
- As-of selection algorithm (§4.1 of plan)
- Leakage rule for risk band (§4.5)
- Sign convention & metric choices (nMAE over MAPE)

## 5. API Contract Summary
- Table of endpoints with query params & key response fields
- Error handling philosophy (404 for gaps, 422 for validation)

## 6. Frontend Architecture
- Routes, state management, charting library, UI components
- UX principles (as-of timestamp visibility, units, tooltips)

## 7. Deployment & Operations
- Docker compose for local
- Vercel serverless (primary) + Heroku (fallback)
- CI pipeline (ruff, mypy, pytest, lint, build, drift check)
- Cold-start & bundle size considerations

## 8. Testing Strategy
- Property tests (hypothesis) on as-of join
- Golden fixture, API tests, contract test, Playwright smoke

## 9. Remediation Plan (from ARCHITECTURE_REVIEW.md)
- Table of all findings with severity, status, owner, ETA

## 10. Known Limitations & Caveats
- Metered wind only, one month, cutoff assumption, no auth, data licence
```
